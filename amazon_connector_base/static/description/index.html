Amazon Connector (SP-API)

Stores the credentials for one or several Amazon accounts, manages the access token, and exposes a generic method to call any SP-API endpoint from other modules.

How it works, step by step

  1. An Amazon account is registered for each seller profile you need to connect (several active accounts are supported at once, each with its own LWA credentials — Client ID, Client Secret, Refresh Token — and its own region: Europe, North America, or Far East).
  2. Each account chooses which marketplaces it operates in, from its own catalog (country + Amazon marketplace ID). Modules that implement actual business logic (e.g. returns) read this list to know which marketplaces to request data for.
  3. When a module needs to make a call, this module checks whether the current access token is still valid (it expires every hour); if it's about to expire or already has, it requests a new one from Amazon using the Refresh Token, without the caller having to worry about it.
  4. The HTTP request is built and sent to the correct URL for the account's region, with the token in the header. If Amazon responds with an error, the HTTP code (401, 403, 404, 429, 500...) is translated into a clear message instead of leaving the raw error.
  5. Every call is logged — endpoint, method, parameters sent, response code, and the error if there was one — in a log viewable from the UI, with a wizard to clean up old entries when needed.
  6. For endpoints that return paginated results, there's a separate method (call_paginated()) that handles pagination automatically — the calling module just has to iterate over the results without managing the page token itself.

Configuration

Everything is configured from Amazon Connector → Connector Settings:

  • API Connections — registration and credentials for each Amazon account.
  • Marketplaces — catalog of country + marketplace ID, and which marketplaces each account uses.
  • API Call Log — history of requests made to Amazon, with their result.
  • Advanced Settings — general connector settings.

Technical note

This module is the base on which specific modules are built (e.g. "Amazon Returns"). It is not functional on its own for any concrete business process — it only provides the connection infrastructure those modules rely on.
